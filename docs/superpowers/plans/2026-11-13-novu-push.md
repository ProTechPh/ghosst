# Novu Push Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace OneSignal with the self-hosted Novu at `novu.astrixstudio.tech` for the three existing broadcasts (new product, restock, admin announcement), with per-device FCM token registration and no change to the callers.

**Architecture:** The Flutter app fetches its FCM token and posts it with the existing anonymous `InstallId` to a new public `POST /v1/push/register`; the PHP API creates a Novu subscriber, stores the FCM token, and subscribes it to topic `ghosst`. `push_send()` triggers one Novu workflow to that topic. Everything stays fire-and-forget.

**Tech Stack:** Flutter 3.47 / Dart 3.11, `firebase_messaging`, PHP 8 on Hostinger + MySQL, Novu REST (`/v1/subscribers`, `/v1/events/trigger`, `/v2/topics`), cURL.

**Spec:** `docs/superpowers/specs/2026-11-13-novu-push-design.md`

## Global Constraints

- No account id, email, or coin data leaves the app for push. Subscriber id = `InstallId` (32 lowercase hex).
- `push_send()` and the register path never throw and never fail the caller; failures go to `error_log` only.
- Broadcast only from `PUSH_HOST` (default `ghossthub.com`); every other host logs `push skipped`/`push register skipped`.
- Timeouts: connect 3 s, total 5 s, on every Novu call.
- Topic `ghosst`, not Novu Broadcast (the environment may be shared with other AstrixTech apps).
- The three existing callers of `push_send()` (`products.php:131`, `keys.php:57`, `announcements.php:69`) are not edited.
- CI gate: `flutter analyze` then `flutter test`; PHP gate: `php ghosst-web/api/tests/rewards_test.php` and the new `push_test.php` both print `ok`.

## Review Focus

- Novu slow/down while an admin adds keys → `POST /v1/admin/keys` still returns 200 with the keys saved.
- Malformed `installId` / token (empty, 99 chars, non-hex, 5000 chars) → 400 `invalid_push`, never a 500 or a Novu call.
- Novu answers 409 because the subscriber or topic subscription exists → treated as success, token refreshed.
- Firebase missing / Play Services absent / token refresh fires on a dead session → app and chat still work, no crash.
- Notification with the app killed → Android shows it (Novu Push step sends an FCM `notification` message; no background handler).
- Already-installed APKs go silent after deploy until they update (accepted in the spec; task 4 verifies the new build only).

```php
<?php
declare(strict_types=1);

/** POST /v1/push/register — FCM token ng device papasok sa Novu.
 *  Public: push must reach the signed-out landing page too. */
function push_register(array $ctx): array
{
    $body = read_json();
    $target = push_target((string) ($body['installId'] ?? ''), (string) ($body['token'] ?? ''));
    if ($target === null) {
        throw new ApiError(400, 'invalid_push', 'installId and token are required');
    }

    push_register_device($target['installId'], $target['token']);

    return ['ok' => true];
}
```

```dart
class Push {
  Push._();

  /// Set once the splash (and the launch gates behind it) are done.
  static bool splashDone = false;

  static bool get canAsk => splashDone;

  /// Firebase is already up (ChatService.init runs first): ask for the FCM
  /// token, hand it to the API, and repeat on every rotation. Never throws.
  static Future<void> init() async {
    try {
      final token = await FirebaseMessaging.instance.getToken();
      await _register(token);
      FirebaseMessaging.instance.onTokenRefresh.listen(_register);
    } catch (_) {}
  }

  static Future<void> _register(String? token) async {
    if (token == null || token.isEmpty) return;
    try {
      await Backend.registerPush(installId: await InstallId.get(), token: token);
    } catch (_) {}
  }

  static Future<void> requestPermission() async {
    if (!canAsk) return;
    try {
      await FirebaseMessaging.instance.requestPermission();
    } catch (_) {}
  }
}
```

Imports: `package:firebase_messaging/firebase_messaging.dart`, `install_id.dart`, `worker_backend.dart`.
